# Quorum V1.1 (`v1.1-diversified`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the preregistered V1.1 research family on a 30-ETF universe whose
funds can join after 2005. The stacker's training skips 2020–2022, and the
report carries the pre-named `stacker.ridge` vs equal-weight test.

**Architecture:**
- **Calendar.** A new `universe.py` derives a master calendar, per-fund
  offsets, and entry positions from the snapshot. The research runner and the
  stitched-portfolio path index everything by master position and map to each
  fund's own bars.
- **Risk policy.** It accepts a growing universe and an optional `2/N_t`
  per-fund cap.
- **Report.** New analysis (per-period table, primary test, IC by cohort) is
  written outside the existing `metrics_sha256`, so old results keep their
  fingerprints.

**Tech Stack:** Python 3.13, numpy, pandas, and pytest. The existing Vibe
`GlobalEquityEngine` and the yfinance loader. No new dependencies.

**Spec:** `docs/quorum/DIVERSIFIED_DESIGN.md`, approved 2026-10-06.

  or `C:\quorum-ws\runtime`.
- The research workspace is `C:\quorum-ws\research`. Tests and checks run on
  scratch copies; only Task 8 registers anything in the real ledger.

**Running Python and tests**

- Run Python from `agent/` with `../.venv/Scripts/python.exe`.
- Run pytest with
  `--basetemp="$SCRATCH/pytest/<name>"`, where `$SCRATCH` is the session
  scratchpad. The default temp directory is not writable.
- Quorum suite baseline: 518 passed (`tests/quorum`). The full-suite baseline
  is 14 failed and 11 errors, all platform-related.

**Results and identity rules**

- `metrics_sha256` keeps its exact definition: the canonical JSON of
  `{"evaluation", "portfolio", "incremental"}`. Nothing new may enter those
  three dicts for snapshots without late funds.
- New `ResearchConfig` fields enter `config_id` only when they differ from
  their defaults. `code_id` becomes `quorum:research:v4`.
- Never fill a missing bar. Calendar violations raise `ValueError`, and the
  attempt is recorded as FAILED, as today.

**Values from the spec**

- Entry is on the fund's `entry_bars`-th own bar, where `entry_bars` is the
  largest `_EXPERT_INPUTS` requirement in the config's expert set: 253 for
  `v1`, 50 for `v0`.
- The training exclusion is 2020-01-01 to 2022-12-31 in America/New_York
  dates. A label interval overlapping it removes the position from stacker
  training only.
- The primary test is `stacker.ridge` at `slippage-15bp` against the equal-weight
  benchmark: `evaluation.sharpe_difference_test`, one-sided, α = 0.05, seed 0.
- The periods are 2006-01-01 to 2019-12-31, 2020-01-01 to 2022-12-31, and
  2023-01-01 to 2024-12-31.

**Git**

- Work on branch `feat/v1.1-diversified` off `main`. Commits are authored as
  DPLCoding, with no Claude co-author line (the user's standing rule).
- Push only when the user says so. The branch merges to `main` through a pull
  request.

## Spec clarification (record in the design doc in Task 3)

**Stacker training rows.** These keep today's rule for every fund: any training
position whose features are complete. Today, funds present from the start
already train on positions before their 253rd bar (the V0 features are
complete from bar 50). Restricting that would change every earlier result.
Late funds get the same treatment.

**Entry.** It governs scoring rows, out-of-sample slots, portfolio weights, the
benchmark, and `N_t`. The design's line "Before entry the fund does not
exist… no stacker training data" is amended to "no stacker training before its
features are complete." A fund present from the start has entry position 0.
With the declared 252-bar minimum training, no out-of-sample slot falls before
its 253rd bar, so its behavior is unchanged.

## Review Focus

1. **A fund present from the start whose first Yahoo bar is missing.** It
   would silently be classified as a late fund and lose a year. Task 8 asserts
   that the late set is exactly {XLC, HYG, EMB, BWX, SLV, DBC, DBA, UUP} and
   stops otherwise.
2. **A late fund with a gap after launch.** The loader drops NaN rows, so a gap
   looks like a shorter calendar. It must fail closed (Task 2 test).
3. **A predictor that lacks a decision for an entered fund on some date,** for
   example an expert abstaining. The portfolio path must fail closed and name
   the predictor, fund, and date, never silently shrink `N_t` (Task 6 test).
4. **A fund that ends before the master calendar or enters at or after the
   holdout start.** It must fail closed, because exits are out of scope (Task 2
   test).
5. **`train_exclude` written as JSON lists, with end before start, or with a
   malformed date.** Lists must normalize to the same `config_id`. Invalid
   ranges must raise (Task 4 test).

### Task 2: Universe layout (master calendar, offsets, entry)

**Files:**
- Create: `agent/src/quorum/universe.py`
- Test: `agent/tests/quorum/test_universe.py`

**Interfaces:**
- Produces:

```python
@dataclass(frozen=True, slots=True)
class UniverseLayout:
    calendar: tuple[MarketBar, ...]      # master reference bars (first sorted start fund)
    offsets: Mapping[str, int]           # master index of each fund's first bar
    entries: Mapping[str, int]           # master index of first scored/traded bar; 0 for start funds
    def own(self, asset: str, p: int) -> int: ...          # p - offsets[asset]
    def entered(self, p: int) -> tuple[str, ...]: ...      # sorted funds with entries[a] <= p
    @property
    def late(self) -> tuple[str, ...]: ...                 # funds with offsets > 0

def universe_layout(
    bars_by_asset: Mapping[str, Sequence[MarketBar]], *, entry_bars: int, holdout_bars: int
) -> UniverseLayout
```

- **Rules.**
  - Start funds have the earliest first bar. They must match exactly; any
    difference raises `ValueError` containing "calendar", as today.
  - A late fund's `(start_at, event_at)` list must equal `calendar[offset:]`.
  - A late fund's entry is `offset + entry_bars - 1`, which must be
    `< len(calendar) - holdout_bars`.
